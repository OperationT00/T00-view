# PikPak Web 适配模块

> 2026-10-09 范围调整：当前聚焦 PikPak 分享链接路由与在线文件夹。每条链接独立保留原目录结构，左侧入口为 `pikpak`；观看入口已暂停，旧播放路由返回目录。后文播放相关说明保留为历史实现记录。详见 [当前设计](../../docs/pikpak-share-playback-design.md)。

这是独立核心 `../pikpak` 的 Spring MVC、HTTP 和 JDBC 适配层。宿主通过 `PikPakConfiguration` 装配，不依赖收藏、标签或账号业务。前端入口为 `/#/shares`。

## 配置

- `PIKPAK_ENABLED=true` 启用接口；默认关闭。
- `PIKPAK_SECRET_KEY` 是随机32字节密钥的Base64字符串，用于AES-GCM加密分享提取码。妥善备份；已有数据时不可直接换成新密钥。
- `PIKPAK_PROXY_URL` 可选，仅作用于此模块的上游HTTP请求。例如 `http://127.0.0.1:7897`。仅支持无账号密码的HTTP CONNECT代理；不影响数据库和其他模块。容器内的127.0.0.1表示容器自身，应填写实际可达地址。

Windows本机实测：默认Java网络读取上游失败；启用现有系统代理后目录读取成功。云服务器需独立验证其网络，不能沿用本机结论。

分享接口由宿主精确放行匿名访问，写请求仍需 `/api/auth/csrf` 返回的令牌及同一会话Cookie。管理员／看客限制仍适用于原收藏系统。

## 当前实现与限制

已实现链接增删改查、20条以内批量添加、身份去重、版本冲突校验、提取码加密、目录按需读取及分页、临时媒体地址查询。上游接口固定，媒体地址限定为已知PikPak CDN域名形态。不会执行账号登录、转存或远端删除。

播放器已有MP4、HLS和MPEG-TS接入、版本切换和本地续播；10.44秒H.264样本已在网页播放至结尾，完整文件分段读取及解码通过。拖动、刷新续播及清除进度已通过浏览器回归，其他编码及长视频仍待验证，见 [验证记录](../../docs/pikpak-playback-verification.md)。当前无服务端播放会话、媒体代理、目录缓存或自动检查状态。详细待办和验收要求见 [设计文档](../../docs/pikpak-share-playback-design.md)。

从仓库根目录执行 `mvn -pl modules/pikpak-web -am test` 可独立运行核心和适配层测试。H2测试验证存储契约；不能代替真实MySQL、网络和浏览器验收。
