# PikPak 真实播放验证记录

日期：2026-10-09。环境：本机Windows、Codex内置浏览器、Java21、MySQL8.4；PikPak元数据请求经本机HTTP代理。

## 已观察到的结果

用户提供普通短视频分享后，测试库完成添加、目录读取、点击视频、获取临时媒体地址并在本站播放器起播。浏览器报告1280×720，时长10.440567秒。播放器曾在9.936086秒缓冲（readyState=2），随后恢复，最终返回：

```json
{"currentTime":10.440567,"duration":10.440567,"ended":true,"paused":true,"readyState":4}
```

源文件元数据显示H.264视频和AAC音频；音频轨存在不等于已通过人工听音验收。原始文件声明大小1849273字节；最后1024字节Range请求返回206并收到1024字节。全文件下载曾因30秒超时中止，不能把当时的部分下载算成完整性验证。浏览器最终播放结束的证据独立于下载探测。

刷新媒体地址后再次通过本机代理下载，55秒仅收到151552字节后超时，未执行完整解码。说明当前网络传输存在明显波动；不能把浏览器曾成功结束推断为稳定播放已验收。后续需比较浏览器直连与服务器转发路径，并在实际部署网络复测。

进一步验证：重新获取地址后，将同一文件按256KiB分成8段，以4个并发请求读取，8段均返回206、退出码0、实际长度等于请求长度。合并文件大小1849273字节，FFmpeg从头到尾解码退出码0，无错误输出；ffprobe时长10.440567秒。该结果支持样本文件完整且可解码，不能单独证明浏览器拖动或所有网络下传输稳定。分段下载脚本仅为诊断，尚未作为生产播放代理接入。

## 当前运行入口

已在本机开发配置启用PikPak模块，`http://127.0.0.1:8080/#/shares` 可添加、管理、打开分享；用户的新测试分享已录入。该环境通过独立代理配置成功取得媒体版本，无需后台账号登录、转存或删除原文件。

## 开发入口浏览器回归

在8080开发入口使用同一分享完成：

- 点击进度条定位到5.939579秒，刷新后显示“已恢复上次进度”，实际currentTime仍为5.939579秒、readyState=4。
- 再定位到9.673891秒（超过总时长90%），点击播放，最终显示“播放结束”，ended=true且currentTime=10.440567。
- 清除本视频观看记录后显示“记录已清除，本次观看不再保存进度”；刷新后currentTime=0、readyState=4，没有续播提示。首次等待超时，随后读取页面确认已加载完成。

这些结果验证了该样本的拖动、刷新续播、后半段播放及清除记录功能，不代表长视频或所有编码的兼容性。

## 尚未证明

- 人工确认声画、长视频完整播放、HEVC和转码版本兼容性。
- 云服务器网络及移动端浏览器。
- 免费账号临时转存、观看后永久清理释放空间：尚未实现，本样本直连成功不代表所有分享均支持直连。

此前旧标签停留在浏览器生成的连接失败页面，工具拒绝操作其data协议地址；重新打开正常HTTP开发页面后验证已恢复，未绕过协议限制。测试签名URL及凭据仅保留在忽略目录，不写入本记录。以上证据支持“本样本在本机网页完整播放结束，拖动及进度管理可用”，不支持“设计文档全部功能已完成”或“任意分享均可完整观看”。
