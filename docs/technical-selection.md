# 私密多源媒体管理器：技术选型建议

更新日期：2026-10-08。本文记录选型及后续候选方案；首版应用已开始实现，当前范围和验证结果见 [README](../README.md)。尚未连接个人网盘、上传素材或购买云资源。

## 已确认的需求

- 用户主要使用 Java / Spring Boot，项目用于个人使用和后端能力实践。
- 准备部署到自购云服务器，电脑和手机使用网页访问。
- 需要整理检索、跨存储定位和私密浏览。
- 结构化信息使用 MySQL 一类关系数据库；图片文件独立存储。
- 视频原资源继续放在硬盘或现有网盘，系统维护位置引用。
- 素材具有隐私性；真实收藏与演示数据使用独立数据集和凭据。
- 用户角色为管理员 ADMIN 和看客 VIEWER：管理员可以维护业务内容，看客只读。默认所有账号登录后查看同一收藏库，账号管理仅管理员可用。
- 以层级标签整理资源，例如 Cos / 公孙离；一个资源可关联多个标签及不同分支。父标签筛选默认包含后代，多个标签默认同时满足。

## 当前推进范围（2026-10-08 补充）

用户决定图片部分先暂定，先推进其他内容。因此，图片、GIF、封面上传和预览，以及 OSS / 私有目录的最终选择均暂缓。以下存储讨论保留为候选方案，不构成当前实现要求。

当前先推进收藏条目、层级标签与多标签整理、存储来源、外部位置、搜索分页和双角色鉴权。管理员维护收藏与账号，看客只读浏览。第一阶段采用手动登记，不读取真实素材、不连接个人网盘、不执行原文件操作。具体功能、表结构和接口建议见 [第一阶段设计](mvp-design.md)。

## 推荐的核心技术栈

| 部分 | 建议 | 原因与边界 |
| --- | --- | --- |
| 云端应用 | Java 21 + Spring Boot 4.1.x + Spring MVC | 沿用用户主技术栈；部署一个应用，按业务划分模块。官方页面当前展示 4.1.1，开工时锁定受支持的补丁版本。 |
| 数据库 | MySQL 8.4 LTS，字符集 utf8mb4 | 保存收藏、标签、来源、对象引用及任务。该版本是候选稳定线，不要求追最新主版本。 |
| 数据访问 | Spring JDBC / JdbcTemplate | 首版使用 JdbcTemplate，SQL、分页、索引和事务行为明确，依赖由 Boot 管理。若用户已有 MyBatis 经验，可以替换此层；需核对 Starter 与 Boot 的兼容性并实际启动验证。 |
| 数据库迁移 | Flyway | 通过版本化脚本维护表结构，避免手工改库。MySQL 支持模块与具体依赖在建工程时核对。 |
| 前端 | Vue 3 + TypeScript + Vite + Vue Router | 一个响应式网页覆盖电脑和手机；前端构建产物由后端同源提供。无需运行时依赖外部 CDN。 |
| 用户身份 | Spring Security + 服务端 Session + ADMIN / VIEWER | 管理员维护业务和账号，看客只读；后端校验角色。Cookie 使用 Secure、HttpOnly 和适当的 SameSite，保留 CSRF 防护。通过 security_version 使停用、角色或密码变更后的旧会话失效。 |
| 图片存储 | 暂定，当前阶段不实现 | 未来可通过存储接口接托管私有对象存储或私有文件目录；先确定收藏和位置模型。 |
| 后台任务 | MySQL 持久任务表 + 有界 ThreadPoolTaskExecutor | 先保存任务，再执行；重启和重试之后依靠幂等操作恢复。线程池本身不提供任务持久化。 |
| 扫描程序 | 后续增加本地 Java 21 Agent，使用 NIO 与 HttpClient | 读取指定目录，主动上报索引；云服务器不能直接扫描用户电脑硬盘。 |
| 部署与访问 | Linux + Docker Compose；个人使用优先评估 Tailscale Serve | 云端应用和数据库使用持久卷；私有网络访问之外仍保留应用鉴权。若采用公网域名，可改为 Caddy HTTPS，但需重新确认暴露范围。 |
| 可观测性 | Actuator 健康状态与脱敏日志 | 首版无需搭建整套监控集群。管理端点按需限制访问。 |

首版已解析 Spring Boot 4.1.1 依赖，并使用 Java 21、JdbcTemplate、Flyway 和独立 MySQL 8.4.11 通过编译及 34 项测试。Docker 镜像构建和云端部署尚未实测；后续图片、Agent 等候选组合也未实现。

## 图片存储如何选择

### 方案 A：托管私有对象存储

对于允许上云的图片和示例素材，优先选择云服务器同厂商、同地域的对象存储，例如腾讯 COS 或阿里 OSS。这样可以将图片容量与应用服务器磁盘分开管理，自己不需要运维一个对象存储服务。

- 存储桶与对象使用私有权限，凭据只保留在后端。
- 后端确认用户权限后，可代理读取图片，或生成短时签名 URL。
- 签名 URL 在有效期内相当于访问凭证，不等于只能由当前登录用户使用；避免进入日志、分析系统和持久化业务数据。
- 若希望退出登录后立即阻止新的读取，优先使用每次请求都鉴权的后端读取入口；已下载到客户端的内容不能远程收回。
- 费用需要同时考虑存储、请求和出网流量，不在尚未明确规模时承诺固定价格。

用户已明确内容具有私密性，且包含可能受服务商条款限制的内容，因此不能直接把 COS/OSS 作为所有真实素材的默认归宿。已核实的 OSS 服务条款明确限制上传、下载、储存色情等内容；私有桶、加密或自建存储服务不会自动改变服务商的适用规则。

### 方案 B：私有文件目录

图片数量和预算还不明确时，文件目录是实现最少、容易验证的起点。

- 真实私密图片可以保留在本地目录，由本地程序提供受控访问；远程访问要求该设备在线。
- 云端也可以使用独立数据盘上的私有目录，但仍属于云端存储，适用云厂商规则。
- 私有目录不放入网页静态资源目录；通过素材 ID 查找文件，每次读取经过鉴权。
- 文件引用采用相对于受控根目录的 key；规范化真实路径并检查符号链接等目录边界。
- 文件持久化在容器外的数据卷，设置容量监测并维护独立备份。
- 扩容、迁移和恢复由自己负责。单台服务器上的一份图片不是备份。

推荐的落地方式：演示环境先用非敏感图片完成一个私有目录存储实现；需要云端图片服务且内容适用服务条款时，再实现 COS 或 OSS 适配器。真实收藏是否迁移，应依据隐私要求和具体服务的适用性单独决定。

### 首版不选自建 S3 兼容服务

首项目没有明确需要独立对象服务时，自建服务会增加部署、升级和恢复工作。MinIO 社区仓库已于 2026-04-25 归档，README 明确表示不再维护，因此不将旧版 MinIO 社区服务作为新项目默认选择。这不等于 MinIO 的商业产品或所有替代产品停止维护。

存储接口只表达业务需要的上传、读取、删除和元数据查询；不预先实现多个云厂商，不假设它们的 SDK 或签名 URL 能互相替换。

## MySQL 与文件之间保存什么关系

收藏条目、专题清单和物理位置分开建模。由于第一阶段先做手动目录，`asset` 表示一条逻辑收藏内容（一个视频或一套图）；套图内逐文件的结构留待扫描、图片处理阶段引入独立文件层，避免第一版要求用户逐张登记。

建议的主要实体：

- `collection`：可选的专题清单，通过关联表包含多个收藏条目；第一阶段暂不实现。
- `asset`：视频、套图或其他资源的逻辑收藏条目，包含标题、类型、说明等。
- `tag`、`asset_tag`：通过 parent_id 表达单父层级，通过多对多关联让一个资源同时具有多个标签。只存直接标签，父及后代筛选用递归 CTE；同级重名、循环、移动及删除规则见第一阶段设计。
- `storage_source`：本地设备、网盘账号或云存储后端。
- `asset_location`：某个素材的物理位置、可用状态、文件大小、可选校验和。
- `job`：同步、导入、缩略图处理或删除任务。

图片位置保存 `storage_backend`、`bucket`（适用时）、`object_key`、大小、MIME 类型、尺寸和可选校验和。缩略图与原图分别关联位置。

视频位置保存来源 ID 和来源中的文件标识。本地视频的绝对路径映射尽量保留在 Agent，云端使用不透明标识关联。

首版图片二进制不放 MySQL，业务记录不持久化临时签名 URL，也不通过文件名或大小直接认定内容相同。

## 同步、任务与文件一致性

- 上传采用“待上传—已确认—可用”的状态；文件写入成功而数据库失败时，通过补偿任务处理孤立文件。
- 删除先标记业务状态并隐藏，再通过持久任务删除系统管理的副本；删除索引或缩略图不连带删除硬盘、网盘中的原资源。
- 任务设置重试次数、下次执行时间、租约或恢复机制；不能声称恰好执行一次。
- Agent 按批次主动上报，云端按设备及批次 ID 幂等接收；网络超时后允许重复发送。
- 来源离线、扫描取消或目录无权限时保留原记录。只有完整成功的扫描才进入缺失核对流程。
- 扫描元数据与用户标签分别更新，避免扫描覆盖手动整理成果。
- 全量内容哈希按需在本地计算，限制磁盘读取并发；相似图片识别留到后续。

## 手机预览与视频边界

- 云端已有图片：手机通过相同网页访问受控图片入口。
- 本地图片：手机远程预览需要在线的本地服务和可达的私有网络；只有云索引不足以提供原图。
- 网盘视频：首版保存位置并提供可用的定位入口。列目录、获取播放地址、登录态和直链有效期需要逐个平台验证。
- 本地视频：首版展示位置和在线状态。远程播放需要另行实现鉴权、Range 请求、连接恢复并验证浏览器编解码支持。
- ffprobe 可在本地提取时长和编码信息；FFmpeg 截帧按需增加。首版不承担视频转码或云端中继流量。

## 隐私边界与备份

服务端可查询的标题、标签、文件名和位置索引也属于敏感信息。当前设计不是端到端加密方案，不能承诺云服务商或服务器管理员无法读取数据。若这个条件不可接受，需要重新设计客户端加密、搜索和密钥管理。

真实库、演示库使用不同数据库、存储根目录或桶、账号凭据及运行配置。日志避免记录文件路径、访问凭据和带签名的 URL。

数据库备份与图片文件备份分别维护，并验证一次联合恢复；不能只备份数据库就认为图片也受到保护。网盘和硬盘的原资源备份由其独立策略负责。

## 首版暂不引入的组件

- Redis、RabbitMQ、Kafka：只有实际出现缓存、独立工作进程或跨实例调度需求时再评估。
- Elasticsearch、向量数据库：先使用标签关联、分页和数据库查询；标题包含搜索需用实际数据量测量，不假设普通索引能够优化所有模糊匹配。
- 微服务、Kubernetes：单实例模块化应用先完成业务闭环。
- PWA 离线素材缓存：后续按隐私策略决定；安装网页不应自动把敏感文件持久缓存到手机。

## 开工前验证

1. 当前阶段先用虚构条目验证管理员/看客权限、收藏、标签、位置关联、分页、账号停用及记录删除行为；图片阶段再验证上传、缩略图和文件补偿流程。
2. 验证依赖版本、MySQL 迁移脚本及数据库备份恢复。
3. 在预期规模的样本上测量查询、批量导入、内存和文件空间，之后再确定服务器规格。
4. 验证手机与电脑的私有网络连通性；明确本地设备离线时可用功能。
5. 后续网盘接入先验证实际授权和权限，再承诺自动同步或播放功能。
