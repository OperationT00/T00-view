# PikPak 分享链接路由与在线文件夹设计

## 当前范围调整（2026-10-09）

新增只读的[疑似重复视频扫描](pikpak-duplicate-scan.md)：递归扫描全部已导入分享，按精确大小列出候选与各自位置，由用户自行判断去留。入口位于 PikPak 分享列表，不新增主侧栏项目。

以分享链接路由和目录浏览为当前交付范围，在线播放暂缓。左侧主导航仅保留一个 `pikpak` 入口。每条唯一分享链接对应一个在线根文件夹；重复导入复用已有记录，不打散、合并或重排原始层级。单链接导入后自动进入目录，多链接导入后各自显示为文件夹入口。

保留上游文件名、文件ID及父子关系，进入目录时通过 `parentId` 按需读取，并支持分页、面包屑、返回上一级、刷新、提取码补填与错误重试。普通文件和视频均展示为文件，不提供播放操作；旧观看页路由返回对应目录。文件目录实时读取，并非全量递归下载或持久化快照；分享失效时保留入口并显示读取错误。链接记录仍存MySQL，原文件不搬运。

以下观看方案及验证结果为历史记录，未完成的播放功能不属于当前交付要求。

### 原始分享链接与导出

列表和详情支持“复制链接”，列表支持“复制全部链接”。全部复制复用完整导出接口，每行一个链接，不受分页或搜索条件影响。只有剪贴板写入成功才提示已复制；浏览器拒绝或不支持时显示可选中的文本供手动复制。TXT导出继续保留。

新增 `original_url` 字段，保存首次成功导入的链接文本（去除首尾空白，保留受支持的显示参数、域名大小写等）。分享ID仍用于去重；重复导入和修改名称、备注不覆盖首次链接。旧记录字段为空，展示和导出时还原 `https://mypikpak.com/s/{shareId}`，并标注“标准链接（旧记录还原）”。

分享列表和目录详情展示可打开的链接，支持单条导出；列表提供“导出全部链接（TXT）”，服务端一次查询全部记录并返回下载附件，不受当前搜索条件或当前已加载50条的限制。TXT为UTF-8，每行一个链接，不包含提取码。通过 `GET /api/pikpak/shares/export.txt` 导出全部，带 `id` 参数导出单条；响应禁用缓存，不需要访问PikPak上游。

### 直接进入官方分享页面

分享卡片与目录详情的主操作为“打开分享页面”，通过普通HTTPS链接在新标签页打开该分享保存的原始URL，旧记录使用标准分享URL。页面明确标注“PikPak 网页版”，不依赖剪贴板或客户端协议；提取码、失效分享等由官方页面处理。Windows客户端入口收纳为辅助选项，明确说明需手动粘贴。这是官方网页直达，不代表已实现Windows原生客户端内部的分享页直达。

### Windows 复制并打开客户端

分享卡片和目录详情提供“复制并打开 PikPak”。先复制该分享原始链接（旧记录使用还原的标准链接），复制成功后请求 `pikpakapp://mypikpak.com/drive/main_tab` 唤起客户端。不附带 add_url，不自动创建下载、转存或分享任务。不把文件ID作为分享链接。

自动复制失败时展示可选中的链接，用户 Ctrl+C 后自行点击“已复制，打开 PikPak”。提供“再次打开 PikPak”和“打开官方分享页”备用入口。仅 Windows 启用；浏览器可能询问是否允许打开外部应用，网页无法可靠判断应用是否已安装或成功打开，因此只显示“已请求打开”。客户端未自动识别时手动粘贴；提取码另行输入。部署时使用 HTTPS 以支持剪贴板接口。

本机2.7.8.5114静态代码注册了pikpakapp协议并处理drive/main_tab；剪贴板监听只匹配magnet/thunder/ed2k。本功能不承诺自动识别HTTPS分享或自动播放。

验证：前端类型检查、生产构建及JAR打包通过；针对真实组件脚本验证了复制完成前不唤起、重复点击不重复复制、复制失败不唤起、非Windows禁用、分享变化后不执行旧唤起。浏览器页面已确认入口可见，真实按钮点击触发外部协议时被浏览器自动化安全策略拦截，未绕过；Windows客户端实际弹出尚未完成端到端验收。

## 1. 本期范围

只做分享链接管理和在线观看。任何使用者都能添加、解析、浏览和观看；“上传链接”指提交URL和可选提取码，不上传视频文件。

本模块按无需登录设计，不区分管理员和看客，不设置草稿、审核、发布、创建者专属权限。链接保存后立即进入共享列表；编辑、删除、重新解析也按共同管理设计。删除只影响本站记录，不删除网盘原文件。

本设计替代上一版分享方案。本期不依赖标签解析、收藏绑定、导入确认、账号网盘扫描、转存或自动删除。现有名称解析核心保持独立，后续再接。

新分享页面及明确列出的接口已设置公共访问，既有收藏和账号接口保留原登录和角色规则；真实MySQL集成测试覆盖此边界。

## 3. 三个页面与流程

流程：粘贴链接 → 保存并读取目录 → 选择视频 → 站内播放 → 本浏览器续播。失败时保留链接和明确状态，补提取码后可重试。

| 页面 | Hash路由 | 功能 |
| --- | --- | --- |
| 分享管理 | /shares | 添加／批量添加、名称备注编辑、搜索、删除、重新解析、最后检查状态 |
| 分享内容 | /shares/:id?folder=:entryId | 面包屑、文件目录、大小、视频过滤、分页、提取码补填、播放按钮 |
| 视频观看 | /shares/:id/watch/:entryId | 播放器、同目录视频列表、上一条／下一条、可用清晰度、倍速、全屏、重新获取地址 |

单视频分享也由用户点击播放。桌面为播放器加侧栏，手机为播放器加下方列表。路由只带本地ID，不带提取码或临时媒体地址；刷新页面重新解析播放地址，返回时保留目录位置。

列表搜索名称和备注；目录过滤明确显示“当前目录已加载文件”，不冒充全量跨分享搜索。默认展示文字和文件类型图标，图片／GIF预览不加入本期。

## 4. 链接管理与文件发现

先支持HTTPS、精确域名mypikpak.com及标准路径/s/{shareId}，shareId保留大小写。带子目录的/s/{shareId}/{folderId}已有开源样例，实测通过后启用，不能把附加段当提取码。未验证域名别名和短代码明确提示不支持。

标准URL解析器拒绝异常端口、账号信息和不合法路径。展示参数不参与身份；提取码独立输入，若支持pwd查询参数则解析后从规范URL移除，日志不得保留秘密。

唯一键(provider, providerShareId)；重复提交返回已有记录，不自动覆盖名称或提取码。子目录是打开位置，不创建第二份分享；每次导航独立。

批量最多20条，分别返回新增／重复／输入错误。保存与解析分开：保存成功后自动请求解析，解析并发最多2个，网络失败仍保留记录，避免用户重复添加。

目录按需分页，每页最多100项，点击视频才取得媒体地址。远端文件ID标识条目，同名文件不合并。缓存建议5分钟，返回检查时间和下一页游标；游标绑定分享与父目录。

完整刷新全部分页后才标记旧文件缺失；部分读取或超时不能推断远端删除。循环目录、重复游标和异常响应中止并保留部分结果。

## 5. 模块和播放路径

独立工程为 `modules/pikpak`，不是宿主后端中的普通业务包。模块只写PikPak相关功能，核心入口为 `PikPakModule`；`PikPakShareGateway` 和 `PikPakShareStore` 分别隔离网络与存储。后续HTTP、JDBC和Web适配仍属于PikPak模块，宿主仅负责装配。前端独立目录为 `frontend/src/modules/pikpak/`，通过自身API访问模块，不引用收藏、标签或用户状态。API实施时统一使用 `/api/pikpak/` 命名空间，下文路径名不变，替代早期 `/api/v2` 前缀。

ShareService负责共享链接、元数据缓存及版本；PikPakShareProvider负责固定上游接口、提取码及媒体解析；PlaybackService负责临时播放地址、媒体版本和失效恢复；MediaGateway只在转发模式下流式传输。名称解析器不依赖这些模块。

播放器取得variantId、protocol、mimeType、已知codecs、qualityLabel及可选expiresAt。版本名称以真实返回为准，不硬编码medias[1]为高清，不编造有效期。

| 方式 | 条件 |
| --- | --- |
| DIRECT优先 | 浏览器可访问、必需请求头可满足、无后端出口绑定；流量不经过应用服务器 |
| RELAY备用 | 后端可读取而浏览器受跨域、请求头或出口绑定影响时，按部署配置使用受控转发 |
| 明确不可用 | 分享失效、上游需要授权／验证码、格式不兼容或播放受限，说明原因并提供重试 |

本站不登录不等于PikPak保证匿名可读。转发只能解决传输兼容问题，不能声称解除上游内容、时长或访问限制。打开原分享可作用户主动选择的备用操作，但不代替本站播放。

MP4等原生兼容格式由ArtPlayer底层video播放；HLS优先原生支持，必要时用hls.js，卸载组件时销毁实例。播放器库不能解码所有MKV／HEVC文件；优先选择已有兼容版本，无可用版本则提示，首版不做服务器实时转码。

普通video与HLS的跨域要求不同，应分别实测；后端HEAD成功不能证明浏览器可播放。清晰度切换保留时间点；不预加载所有视频地址。

## 6. 临时会话与进度

创建会话绑定分享、文件、版本；会话用于生命周期和容量控制，不绑定用户或要求登录。建议空闲30分钟、最长8小时，播放中每60秒心跳；暂停超时后重新创建。媒体URL及验证token仅放有界TTL内存缓存，重启后重建。

地址疑似过期时后端复核原因，合并并发刷新，最多自动重新解析一次，恢复当前位置；再次失败由用户点击重试。429遵循Retry-After，网络故障有限退避，验证挑战和明确拒绝不无限重试。

观看进度放本浏览器localStorage，以平台／分享ID／文件ID为键，每15秒及暂停结束时更新。只保存时间和时长，不保存媒体URL／提取码。提供从头播放与清除历史；换设备不自动同步，存储不可用仍能观看。

修改提取码或删除链接递增版本／失效相关缓存和播放会话；已发给浏览器的直连地址由上游决定何时失效，不能保证即时撤销已经缓冲的内容。

## 7. 最小数据与公共API

| 存储 | 内容 |
| --- | --- |
| share_source | 平台与分享ID、规范URL、默认目录、名称、备注、检查状态时间、错误码、version、创建更新时间；分享身份唯一 |
| share_secret | share_id、加密提取码、密钥版本；密钥与数据库分开，API不原样返回秘密 |
| share_entry | 本地ID、分享ID、远端文件和父ID、名称路径、类型、大小、时长、检查和缺失时间；分享加远端ID唯一 |
| 有界内存 | 播放sessionId、shareVersion、entryId、variantId、媒体URL及到期、验证上下文 |
| 浏览器本地 | 观看进度及上次打开的目录 |

不设发布状态、用户所属关系、watch_progress用户表或收藏绑定表。编辑用version检查并发冲突；删除清理本站条目和会话，不调用远端删除。批量删除提供普通操作确认，所有使用者都能操作。大小用BIGINT存储、API十进制字符串传输。

以下计划API均使用/api/pikpak前缀，无登录或角色门槛：

| 方法与路径 | 功能 |
| --- | --- |
| GET /shares | 分页和搜索 |
| POST /shares | 添加，重复返回已有ID |
| POST /shares/batch | 最多20项，逐项结果 |
| GET /shares/{id} | 详情和检查状态 |
| PUT /shares/{id} | 修改名称、备注及提取码，带version；秘密区分保留／替换／清除 |
| DELETE /shares/{id}?version=... | 删除本站记录 |
| POST /shares/{id}/inspect | 检查分享和提取码 |
| GET /shares/{id}/entries?parentEntryId=...&cursor=... | 目录分页，校验父目录确属该分享 |
| POST /shares/{id}/refresh | 显式刷新指定目录 |
| POST /playback-sessions | 用shareId、entryId及可选variantId取得本次播放信息 |
| POST /playback-sessions/{id}/refresh | 地址刷新或切换已返回的媒体版本 |
| POST /playback-sessions/{id}/heartbeat | 延长空闲期 |
| DELETE /playback-sessions/{id} | 关闭本地会话 |
| GET/HEAD /playback-sessions/{id}/media/{resourceId} | 会话内服务端映射的媒体资源，不接收任意外部URL |

进度无需服务端API。错误区分输入错误、提取码、上游验证／授权、限流、不可用、编码、地址过期及部分播放限制；未知错误不一律解释为分享已删除。目录可访问不等于全部视频可完整播放。

## 8. 必要实现约束

这些约束不新增角色、审批或登录流程。

- 公共前端路由在全局登录守卫调用auth.ensure之前处理，登录接口失败也不阻止分享页面。
- 后端精确放行上述路径与方法；公共写请求保留同源／CSRF校验，匿名访问者可直接获得CSRF令牌；媒体GET不要求自定义CSRF请求头。
- Provider固定接口，媒体URL及重定向、HLS内嵌URI校验HTTPS、允许目标域名和实际连接IP，拒绝私网、环回和云元数据地址。不能成为任意URL代理。
- RELAY有界缓冲、背压和取消，正确处理GET／HEAD、单段Range／If-Range、206／416；上游忽略Range不伪造206，不为拖动下载整个文件。
- 已向浏览器输出字节后失败，结束该响应再由播放器恢复，不能拼接不同版本；HLS按需映射子清单、分片及合法密钥URI，只转发清单不算完成。首版不支持直播／DRM。
- 按实际媒体域名调整CSP；HLS另配置必要connect-src、blob和worker。no-referrer、日志脱敏、名称按纯文本显示；临时凭据不入持久浏览器缓存。
- 建议连接超时5秒、元数据读取15秒、响应2 MiB上限；解析和转发独立限流，批量解析不挤占播放。转发容量通过部署配置设置，无管理员专属页面。
- 维持单实例内存会话，不新增Redis、消息队列或OSS；引入依赖时固定版本，正式迁移沿用Flyway增量方式。
