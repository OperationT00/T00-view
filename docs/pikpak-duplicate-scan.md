# PikPak 疑似重复视频扫描

实现范围：全部已导入的 PikPak 分享，递归目录和全部分页，只读取目录元数据，不解析播放地址，不下载、转存、删除或合并视频。

## 判断及结果

- 当前唯一匹配依据为大于零的精确文件字节大小；同大小视频分组为“疑似重复”，不是内容相同的证明。
- 文件名称不限制匹配，因此改名副本也可以被列出；转码、剪辑后大小改变则可能漏检。
- 大小为空或零不参与比较，单独统计。相同分享中重复返回的 fileId 只计一次，跨分享保留各个位置。
- 每个结果包含名称、分享名称、原始分享链接（旧记录使用标准链接）、fileId、完整目录路径、大小。可以定位在线文件夹或打开原分享。
- 支持 JSON 导出，保留所有组和扫描完整性信息。结果为扫描时快照，来源后续变化可能使定位失效。

## 任务及接口

核心类 `PikPakDuplicateScanner` 位于独立 pikpak 模块，依赖现有模块门面，不依赖 Spring、数据库或主收藏库。HTTP 层提供：

- `POST /api/pikpak/duplicate-scan`：开始扫描；已有任务运行时返回该任务。
- `GET /api/pikpak/duplicate-scan`：最近一次任务，无任务时为空响应。
- `POST /api/pikpak/duplicate-scan/{id}/cancel`：请求停止指定任务，在当前目录请求返回后停止。

同一服务实例最多一个扫描任务，顺序读取目录；页面轮询进度，关闭页面不停止任务。与现有 PikPak 模块一致公开访问，写请求仍校验 CSRF。

状态为 RUNNING、COMPLETED、PARTIAL、CANCELLED。分享读取失败保留已找到的候选并继续其他分享，明确列出失败分享；中断不能表示扫描成功或“没有重复”。扫描期间检测分享版本变化。分页循环检测、文件夹 ID 去重；上限 5000 条分享、10000 次目录请求、100000 个返回项、32 层目录，超限明确标记不完整。

当前只在内存保留最近一次结果，服务重启清空；重新扫描替换结果，请先导出需要留存的报告。不保证多个服务实例共享任务；适用于当前单机部署。当前不实施哈希或画面相似度算法，也不假定匿名分享接口提供可靠内容指纹。

## 验证

自动化覆盖跨分享及子目录、分页、重复返回、未知大小、改名同大小、同名不同大小、105 个分享、读取失败、分页循环、文件夹循环、重复启动与取消。HTTP 集成覆盖匿名读取与 CSRF 边界。真实分享扫描验证以实际运行结果为准，测试夹具不作为真实内容重复的证据。

2026-10-09 本地验证：前端类型检查与生产构建通过；Maven 共 111 项测试通过（核心 21、适配层 12、主应用 78）。通过页面发起真实扫描，2 / 2 个分享完成，读取 5 页、161 个视频，返回 1 组 2 个位置、大小均为 194960288 字节，无扫描错误。这仅验证候选发现，不证明视频内容相同。
